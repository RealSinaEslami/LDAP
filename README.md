# HTG LDAP API

## اجرا

اطلاعات اتصال ارائه‌شده در فایل `.env` تنظیم شده است؛ در صورت تغییر رمز، آن را در همین فایل به‌روزرسانی کنید.
کلید تصادفی `API_KEY` در همین فایل تولید شده است؛ مقدارش را برای Swagger نگه دارید.
فایل `.env` در Git نادیده گرفته می‌شود و رمز داخل کد قرار ندارد.

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --workers 1
```

صفحهٔ http://127.0.0.1:8000/docs را باز کنید. در Authorize مقدار API_KEY را وارد کنید.

- `POST /data/sync`: خواندن تمام کاربران محدودهٔ LDAP و ثبت یا به‌روزرسانی در SQLite.
- `GET /data/users`: نمایش کاربران با offset، limit و q برای جست‌وجوی نام کاربری.
- `GET /data/users/{uid}`: دریافت کاربر با objectGUID.
- `GET /health`: سلامت برنامه؛ اتصال LDAP را بررسی نمی‌کند.

برای دریافت اطلاعات باید به شبکهٔ سازمان یا VPN مربوط متصل باشید.
فایل دیتابیس پیش‌فرض `ldap_users.db` کنار main.py ساخته می‌شود.

## ساختار

- `main.py`: راه‌اندازی برنامه، جدول‌ها و روتر.
- `config.py`: تنظیمات محیطی.
- `database.py`: engine و session مربوط به SQLAlchemy.
- `models/data_model.py`: مدل جدول کاربران.
- `schemas/data_schema.py`: ساختار خروجی API.
- `services/data_service.py`: اتصال LDAP، صفحه‌بندی و همگام‌سازی.
- `routers/data_router.py`: مسیرهای API و بررسی کلید دسترسی.

فیلد uid از نوع UUID است و به objectGUID نگاشت می‌شود. نام و نام خانوادگی
می‌توانند کوتاه یا خالی باشند؛ محدودیت حداقل چهار کاراکتر حذف شده است.
فیلد مبهم attribute با فیلدهای مشخص LDAP جایگزین شده است.
نام OU تضمین فعال بودن حساب نیست؛ enabled از userAccountControl خوانده می‌شود.

همگام‌سازی یک تراکنش است: اگر یک صفحه خطا دهد، تغییرات آن اجرا برگردانده می‌شوند.
کاربری که در دریافت بعدی وجود ندارد حذف نمی‌شود؛ last_seen_at آخرین مشاهده را نشان می‌دهد.
همگام‌سازی خودکار زمان‌بندی نشده است. به دلیل قفل محلی، تنها یک worker/instance اجرا کنید.

پروتکل فعلی LDAP روی پورت 389 بدون TLS است. اگر سرور StartTLS دارد،
LDAP_START_TLS را true کنید. در صورت نیاز، مسیر گواهی CA داخلی را در
LDAP_CA_FILE بگذارید و LDAP_HOST را مطابق نام گواهی سرور تنظیم کنید.
اعتبارسنجی گواهی غیرفعال نمی‌شود. برای دسترسی از راه دور به API از HTTPS استفاده کنید.

## تست بدون شبکه

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

تست‌ها با دیتابیس حافظه‌ای و LDAP شبیه‌سازی‌شده اجرا می‌شوند.

## صفحهٔ تست و جست‌وجوی تقریبی

پس از اجرای سرور، http://127.0.0.1:8000 را باز کنید. کلید API را وارد کنید،
در صورت نیاز همگام‌سازی کنید و نامی مثل Ali Masoudi را جست‌وجو کنید.
صفحه به اینترنت، فونت خارجی یا نصب ابزار frontend نیاز ندارد و کلید را ذخیره نمی‌کند.
برای افزودن «یاسی»، ابتدا فاطمه را پیدا کنید، مدیریت نام‌های مستعار را بزنید و نام را ثبت کنید.
برای جست‌وجوی فارسی و انگلیسی، هر دو نگارش را به همان کاربر اضافه کنید.
تبدیل خودکار فارسی به انگلیسی یا حدس‌زدن لقب‌ها انجام نمی‌شود.

- `GET /data/users/search?q=Ali%20Masodi&limit=10&min_score=70`: نتایج مرتب‌شده با امتیاز، نام و نوع تطبیق.
- `GET /data/users/{uid}/aliases`: نام‌های مستعار کاربر.
- `POST /data/users/{uid}/aliases` با بدنهٔ `{"name":"یاسی"}`: ثبت نام مستعار.
- `DELETE /data/users/{uid}/aliases/{alias_id}`: حذف نام مستعار.

نام اصلی، نام کاربری، ترکیب نام و نام خانوادگی و نام‌های مستعار بررسی می‌شوند.
ابتدا Unicode، حروف فارسی/عربی، اعراب، بزرگی حروف و فاصله‌ها یکسان می‌شوند.
تطبیق کامل امتیاز ۱۰۰، جابه‌جایی کلمات ۹۹ و شروع کلمات ۹۵ می‌گیرد.
شباهت تقریبی بر اساس Damerau–Levenshtein در RapidFuzz است و سقف ۹۴ دارد.
امتیاز، احتمال درست بودن نتیجه نیست. برای عبارت‌های کمتر از چهار حرف،
تطبیق دارای غلط تایپی غیرفعال است؛ عبارت تک‌حرفی هم فقط تطبیق کامل می‌گیرد.
افراد با نام یکسان یا لقب مشترک به‌صورت چند نتیجه نمایش داده می‌شوند.
برای فقط یک پیشنهاد limit=1 بگذارید؛ اگر آستانه رعایت نشود خروجی خالی است.
پارامتر enabled_only=true کاربران غیرفعال را از نتایج کنار می‌گذارد.

نام مستعار تنها برای همان uid ثبت می‌شود، در LDAP نوشته نمی‌شود و با sync حفظ می‌شود.
جدول جدید user_aliases هنگام راه‌اندازی بعدی به دیتابیس موجود افزوده می‌شود؛
جدول کاربران پاک یا بازسازی نمی‌شود.
نسخهٔ فعلی برای سادگی نام‌ها را در حافظه امتیازدهی می‌کند و هر جست‌وجو
کاربران و نام‌های مستعار را می‌خواند. برای داده و ترافیک بزرگ باید ایندکس جست‌وجوی اختصاصی اضافه شود.

## تولید نام‌های مستعار با آوال‌آی

اسکریپت `generate_aliases.py` کلید را از `LLM_KEY` و نام دقیق مدل را از `LLM_MODEL`
و آدرس سرویس را از `LLM_URL` در همان `.env` می‌خواند. آدرس پایهٔ آوال‌آی `https://api.avalai.ir/v1` است. آدرس کامل `/v1/chat/completions` هم پذیرفته می‌شود. از مدل دارای پشتیبانی JSON mode استفاده کنید؛ خروجی در برنامه با Pydantic اعتبارسنجی می‌شود.

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
# پیش‌نمایش یک کاربر؛ به آوال‌آی درخواست می‌فرستد اما نام‌ها را ذخیره نمی‌کند.
.\venv\Scripts\python.exe generate_aliases.py --limit 1 --dry-run
# ذخیره برای همهٔ کاربران موجود در دیتابیس
.\venv\Scripts\python.exe generate_aliases.py
# فقط یک کاربر مشخص
.\venv\Scripts\python.exe generate_aliases.py --uid YOUR-USER-UUID
```

ابتدا LDAP را همگام‌سازی کنید. امکان `--enabled-only` و `--limit 10` نیز وجود دارد.
مدل نام، نام خانوادگی و نام کامل فارسی، نگارش‌های لاتین و فینگلیش و صورت‌های کوتاه
متداول را تولید می‌کند. برای Pouya Khosravi از مدل حالت‌هایی مانند پویا، خسروی،
پویا خسروی، pooya، poya و puya خواسته می‌شود؛ خروجی واقعی به مدل بستگی دارد.
لقب شخصی نامرتبط از روی اسم قابل استنباط نیست؛ آن را دستی ثبت کنید تا مدل
در درخواست‌های بعدی بتواند از نام‌های مستعار شناخته‌شده استفاده کند.

فقط نام‌ها و نام‌های مستعار فعلی به آوال‌آی و ارائه‌دهندهٔ مدل انتخابی فرستاده می‌شوند،
نه رمز LDAP، ایمیل، تلفن یا DN. هر کاربر یک درخواست دارد و درخواست‌ها ممکن است هزینه داشته باشند.
اسکریپت خودکار در startup یا sync اجرا نمی‌شود. تکرار اجرا درخواست جدید به مدل می‌فرستد،
ولی مقادیر تکراری نرمال‌شده در دیتابیس درج نمی‌شوند.
نام‌های فعلی حذف نمی‌شوند؛ ذخیره برای هر کاربر یک تراکنش مستقل است.
خطای یک کاربر گزارش می‌شود و پردازش ادامه پیدا می‌کند؛ خطاهای تنظیمات API باعث توقف می‌شوند.
هنگام اجرا بهتر است نام‌های مستعار را هم‌زمان در UI تغییر ندهید؛ تعارض درج باعث
برگشت تراکنش همان کاربر می‌شود. خروجی مدل را ابتدا با dry-run بررسی کنید.
حالت dry-run نام‌های پیشنهادی را در ترمینال چاپ می‌کند.
